From a private key to a public key

A small JavaScript experiment with elliptic-curve scalar multiplication and the statistical properties of its outputs.

1. Aim and method

The aim is to calculate a toy public point Q = kG from a private scalar k. Multiplication here means repeated elliptic-curve point addition, rather than ordinary multiplication of coordinates.

Curve: y² ≡ x³ + 7 (mod 17)
Base point: G = (1, 5)
Example private scalar: k = 6

All coordinates and arithmetic are modulo 17. The base point is valid because 5² mod 17 = 8 and (1³ + 7) mod 17 = 8. The symbol O denotes the point at infinity, which acts as the identity: O + P = P.

Point-addition rules and the small core algorithm

For different points P = (x₁, y₁) and R = (x₂, y₂), the slope is λ = (y₂ − y₁)(x₂ − x₁)⁻¹ mod 17. For doubling, λ = 3x₁²(2y₁)⁻¹ mod 17. Then x₃ = λ² − x₁ − x₂ and y₃ = λ(x₁ − x₃) − y₁, both modulo 17. Opposite points add to O.

A modular inverse replaces ordinary division. For example, 10⁻¹ ≡ 12 because 10 × 12 ≡ 1 (mod 17). The following ten-line core handles valid points on this toy curve; the remaining JavaScript displays results and counts frequencies.

2. Dataset: repeat the experiment

Each statistical unit is one scalar choice. The recorded variables are k, the x-coordinate and the y-coordinate of Q. I enumerate k = 1,…,9 to inspect one complete cycle. This is an exhaustive experiment, not a random sample.

One complete cycle
kQ = kGx (5 bits)y (5 bits)

The first eight outputs are finite and distinct; 9G = O. Therefore G has order 9, and (k + 9)G = kG. For example, 10G = G. O has no finite x or y coordinates, so it is excluded from all coordinate and bit statistics below; their denominator is 8.

3. From the dataset to frequency distributions

To obtain a distribution, equal coordinate values are grouped and counted. Absolute frequency is the count; relative frequency is count ÷ 8. These are discrete variables, so no continuous intervals or density estimate are needed.

Only observed values are listed; all other values from 0 to 16 have frequency zero. The x-values 1, 2, 5 and 12 each occur twice (25%). Each observed y-value occurs once (12.5%). Opposite points share an x-coordinate, explaining its repeated values.

If k is chosen uniformly from 1,…,8, each of the eight finite points has probability 1/8. This does not imply uniform coordinates over 0,…,16. Here the exhaustive relative frequencies equal those theoretical coordinate probabilities. A random sample would fluctuate around them.

Bit distribution

Each coordinate is encoded with five bits, including leading zeros. Bit b₄ is the most significant bit and b₀ the least significant.

Bitx: ones / 8y: ones / 8

Bit frequencies are not all 50%. The allowed coordinates and their encoding constrain them: for example, no observed x-coordinate reaches 16, so its b₄ bit is always zero. Bit balance alone is not a test of elliptic-curve security.

Input/output relationship

Pearson correlation measures a linear numerical relationship. A zero or small value does not imply independence: Q is fully determined by k. The sequence also has the exact relation Q(k + 1) = Q(k) + G and repeats after nine steps.

A small input-bit-change experiment

Compare three pairs of valid scalars that differ in exactly one input bit. Encode each output as the 10-bit string x || y and count the changed bits (Hamming distance).

These three comparisons describe only this toy example. They do not establish an avalanche property. For an ideal hash-like mapping, flipping one input bit is expected to change about half the output bits on average; that is not a required criterion for elliptic-curve scalar multiplication.

4. Interpretation and conclusion

The mapping is deterministic and easy to compute forward. On a suitably chosen large curve, recovering k from G and Q is believed computationally difficult because of the elliptic-curve discrete logarithm problem (ECDLP). Our tiny example is easy to reverse by listing the eight possible finite outputs.

Scalar multiplication produces a curve point and preserves a group structure. A cryptographic hash instead produces a fixed-length digest from a message and aims for preimage, second-preimage and collision resistance. Collision resistance means that finding two distinct messages with the same digest is difficult; it does not mean collisions cannot exist.

Coordinate frequencies, bit counts and input-change comparisons describe the chosen dataset. They do not prove one-wayness or security. Ethereum uses secp256k1 with much larger parameters. This program demonstrates the private-to-public-key relationship only; it is not a real Ethereum key generator, encryption system or hash function.
