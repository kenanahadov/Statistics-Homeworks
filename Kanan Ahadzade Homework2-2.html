Toy ECC and the Caesar cipher

Encrypt the same message, compare the results, and recover keys using two different attacks.

1. ECC encryption and decryption

The earlier exercise used a curve modulo 17. This exercise uses the actual secp256k1 curve, y² ≡ x³ + 7 (mod p), where p = 2²⁵⁶ − 2³² − 977, with its standard base point G and order n. Only the receiver's private key is restricted: 1 ≤ d ≤ 1000.

The receiver keeps d secret and publishes Q = dG. For each character, the sender chooses a fresh random scalar r from 1,…,n−1. The sender uses Q, not d.

Encrypt: T = rG, E = M + rQ
Decrypt: M = E − dT
Because E − dT = M + r(dG) − d(rG) = M.

Reversible encoding: printable ASCII characters have codes a = 32,…,126. Encode each as M = (a − 31)G. These 95 points are distinct. After removing the mask, the receiver looks up M in the same public table to recover the character. No original plaintext is needed for decryption. A fresh r is used for every character; the ciphertext is the list of pairs (T,E).

Use 1–80 printable ASCII characters. Run again to obtain fresh ECC ciphertext. Keys and intermediate values are shown for teaching only.

2. Caesar encryption and decryption


Number the letters A,…,Z as 0,…,25. Encrypt with c = (m + k) mod 26
and decrypt with m = (c − k) mod 26. Both parties use the same secret key.
This implementation preserves case, spaces and punctuation.

4. Statistical attack on Caesar


The English reference uses Peter Norvig's published letter frequencies from
a filtered Google Books corpus containing about 3.56 trillion letter occurrences.
The rounded percentages are normalized to sum to one. These are corpus estimates,
not universal language constants.
Reference data and method.



For each candidate shift k, rotate the observed counts back and compare them
with the expected English counts. Choose the smallest score:



χ²(k) = Σ (Oⱼ(k) − Nfⱼ)² / (Nfⱼ), for j = A,…,Z.



N is the number of ciphertext letters; fⱼ is the reference frequency;
Oⱼ(k) is the candidate plaintext count. This uses all 26 letters instead of
assuming the most common one is E. Counting takes O(N) work; scoring needs only
26 × 26 terms. Here χ² is a ranking score, not a significance test or a guarantee
of the correct key. Exact ties select the smaller shift.

5. Attack on the restricted ECC private key


An attacker knows G, Q and the range 1,…,1000. Start at G and repeatedly
add G, checking G, 2G,… against Q. A match gives d exactly.
Then decrypt the intercepted pairs using E − dT.
The search uses neither the original private key nor the plaintext.







The search needs at most 1000 candidate checks, O(B) work for bound B,
and constant working memory. Its success does not depend on the message language
or length. Caesar's attack instead ranks candidates using language statistics
and may choose incorrectly.



For full-range secp256k1, exhaustive search has approximately 2²⁵⁶ candidates.
Even generic square-root classical attacks require about 2¹²⁸ group operations,
making this approach computationally infeasible in practice. A large field alone
is insufficient: the private key must also be drawn from a sufficiently large,
unpredictable range.



This is an educational point-encryption scheme, not production encryption.
Independently of the small key range, it has no authentication and is malleable.
Reusing r would reveal differences between message points. It also reveals
message length. Increasing d's range would not repair those design limitations.



6. Conclusion


Both schemes apply a reversible mask. Caesar preserves letter-frequency
structure, allowing statistical key estimation. The ECC attack exploits the
deliberately small private-key range and verifies guesses using the public key.
These are different weaknesses: a useful statistical model identifies the Caesar
shift, while an exact point comparison identifies the ECC key.
